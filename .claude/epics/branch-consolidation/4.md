# Task: UI/Frontend Consolidation

## Description
Merge trainer-ui-integration and demo-app-integration branches into ccpm-consolidated. This task consolidates Vue 3 components, Vuetify UI patterns, and frontend features from both the MedCAT Trainer UI and the demo application. The goal is to preserve the best components from each branch while eliminating duplication and maintaining consistent design patterns.

## Acceptance Criteria
- [ ] Both trainer-ui and demo-app branches analyzed
- [ ] Component inventory created (no duplication)
- [ ] Vuetify components consolidated
- [ ] Composition API patterns preserved
- [ ] TypeScript types unified
- [ ] All frontend tests passing
- [ ] UI accessibility maintained (WCAG 2.1 AA)
- [ ] Documentation updated with component catalog

## Technical Details
- **Branches to analyze**:
  - `trainer-ui-integration`
  - `demo-app-integration`
- **Key modules**:
  - `webapp/src/components/` (Vue components)
  - `webapp/src/composables/` (Composition API)
  - `webapp/src/views/` (Page views)
  - `webapp/src/types/` (TypeScript definitions)
  - `webapp/src/assets/` (Styles, images)
  - `webapp/src/router/` (Vue Router config)
- **Merge strategy**:
  1. Create component inventory from both branches
  2. Identify duplicates with different implementations
  3. Choose best implementation (or merge features)
  4. Consolidate TypeScript types
  5. Validate with Storybook (if available) or manual testing
- **Conflict resolution priority**: trainer-ui > demo-app (trainer is more mature)

## Subtasks

### 1. Component Inventory (60 min)
- [ ] List all components in trainer-ui:
  ```bash
  cd .worktrees/trainer-ui
  find webapp/src/components -name "*.vue" | sort
  ```
- [ ] List all components in demo-app:
  ```bash
  cd .worktrees/demo-app
  find webapp/src/components -name "*.vue" | sort
  ```
- [ ] Create component matrix:
  - Unique to trainer-ui
  - Unique to demo-app
  - Present in both (compare implementations)
- [ ] Document component dependencies (parent-child relationships)

### 2. Component Deduplication (90 min)
- [ ] **For duplicates**: Compare implementations side-by-side
- [ ] **Decision criteria**:
  - TypeScript coverage (prefer full types)
  - Composition API usage (prefer over Options API)
  - Accessibility (ARIA labels, keyboard nav)
  - Test coverage
  - Performance (minimize re-renders)
- [ ] **Common duplicates**:
  - Patient search components
  - Annotation display components
  - Concept selection components
  - Timeline/history components
  - Modal dialogs
- [ ] Cherry-pick best implementation for each duplicate

### 3. Merge Trainer UI Components (45 min)

### 4. Merge Demo App Components (45 min)
