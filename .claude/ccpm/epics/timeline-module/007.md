**E2E Test Scenarios**:

### User Workflows

1. **Basic Timeline Viewing**:
   ```typescript
   test('User views patient timeline', async ({ page }) => {
     // Login as clinician
     await page.goto('/login')
     await login(page, 'dr.smith@hospital.com')

     // Select patient
     await page.goto('/patients/P12345')

     // Navigate to timeline
     await page.click('text=Timeline')

     // Verify timeline loads
     await expect(page.locator('.timeline-axis')).toBeVisible()
     await expect(page.locator('.timeline-event')).toHaveCount(237)

     // Verify events displayed
     await expect(page.locator('text=Atrial Fibrillation')).toBeVisible()
   })
   ```

2. **Filter Application**:
   ```typescript

     // Apply date range filter
     // Verify timeline updates
     // Verify event count changes
   })
   ```

     // Verify meta-annotations shown

### Performance Tests

1. **Load Testing (Locust)**:
   - Simulate 100 concurrent users
   - Each user views 10 different patient timelines
   - Measure P50, P95, P99 response times
   - Target: P95 <500ms

2. **Frontend Performance (Lighthouse CI)**:
   - Performance score >90
   - First Contentful Paint <1.5s
   - Time to Interactive <3.5s
   - Total Blocking Time <300ms

### Accessibility Tests

1. **Automated Audit (axe-core)**:
   ```typescript
   test('Timeline is accessible', async ({ page }) => {
     await page.goto('/patients/P12345/timeline')
     const results = await runAccessibilityAudit(page)
     expect(results.violations).toHaveLength(0)
   })
   ```

2. **Keyboard Navigation**:
   ```typescript
   test('User can navigate timeline with keyboard', async ({ page }) => {
     // Tab to timeline
     // Arrow keys navigate events
     // Enter opens event detail
     // Escape closes modal
   })
   ```

3. **Screen Reader Support**:
   - ARIA labels for all interactive elements
   - Event markers have descriptive labels
   - Filter controls announce changes
   - Modal announces when opened
