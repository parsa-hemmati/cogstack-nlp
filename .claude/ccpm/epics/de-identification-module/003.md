# Task #003: Create De-identification Service

## Description

Implement `deidentification_service.py` that applies HIPAA Safe Harbor de-identification methods to clinical notes by removing, replacing, or generalizing PHI entities detected by the PHI detection service.

## Phase

Phase 2: Backend API (Week 4-5)

## Technical Specifications

**Goal**: Service that transforms PHI-containing notes into de-identified notes

**Service Design**:
```python
backend/app/services/deidentification_service.py
├── DeidentificationService (class)
│   ├── __init__(phi_detection_service: PHIDetectionService)
│   ├── deidentify(text: str, method: str) → DeidentificationResult
│   ├── deidentify_batch(notes: List[str], method: str) → List[DeidentificationResult]
│   └── validate_deidentification(original: str, deidentified: str) → ValidationReport
```

**Result Schema**:
```python
class DeidentificationResult(BaseModel):
    original_text: str
    deidentified_text: str
    entities_removed: List[PHIEntity]
    method_used: str  # "removal", "replacement", "generalization"
    confidence_score: float  # Average confidence of detected PHI
    review_required: bool  # True if any entity has confidence <0.8
```

## Implementation Requirements

### 1. Safe Harbor Methods

**Method 1: Removal** (Default)
```python
# Replace PHI with placeholder
"Patient John Doe was admitted on 01/15/2024"
→ "Patient [NAME] was admitted on [DATE]"
```

**Method 2: Replacement** (With consistent mapping)
```python
# Replace with synthetic data, consistent within document
"John Doe" → "Patient A"
"01/15/2024" → "[DATE_1]"
# Second occurrence: "John Doe" → "Patient A" (same mapping)
```

**Method 3: Generalization**
```python
# Dates: Keep only year
"01/15/2024" → "2024"

# Ages >89: Aggregate to 90+
"Patient is 92 years old" → "Patient is 90+ years old"

# Locations: Keep only state
"123 Main St, Boston, MA" → "Massachusetts"
```

### 2. PHI Entity Processing
- Call `phi_detection_service.detect_phi(text)`
- Sort entities by start offset (reverse order for replacement)
- Apply de-identification method to each entity
- Maintain character offsets during replacement
- Track all removed entities for audit trail

### 3. Consistency Mapping
- Within a document, same PHI → same replacement
- Example: "John Doe" always → "Patient A"
- Store mapping: `{"John Doe": "Patient A", "01/15/2024": "DATE_1"}`
- Reset mapping for each new document

### 4. Review Flagging
- Flag for manual review if:
  - Any entity confidence <0.8
  - >20 entities detected (high PHI density)
  - Conflicting entity types at same offset
  - Unknown entity type

### 5. Validation
- Check no PHI remains using regex patterns
- Verify text still readable (not over-redacted)
- Ensure clinical context preserved
- Return validation report with warnings

### 6. Error Handling
- PHI detection fails → return error, don't proceed
- Empty text → return as-is with warning
- Too large (>100 pages) → chunk and process
