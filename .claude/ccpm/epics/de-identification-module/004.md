# Task #004: Create Batch Processing API and Celery Tasks

## Description

Implement REST API endpoints for de-identification (single + batch) and Celery background tasks for processing large batches (1,000-10,000 notes) without blocking the UI. Provides progress tracking, cancellation, and result retrieval.

## Phase

Phase 2: Backend API (Week 5-6)

## Technical Specifications

**Goal**: Scalable batch de-identification API with background processing

**API Endpoints**:
```python
POST /api/v1/deidentify
POST /api/v1/deidentify/batch
GET  /api/v1/deidentify/job/{job_id}
POST /api/v1/deidentify/job/{job_id}/cancel
GET  /api/v1/deidentify/job/{job_id}/download
```

**Architecture**:
```
FastAPI Endpoint → Celery Task → PHI Detection → De-identification → Elasticsearch
      ↓
   Job ID returned
      ↓
Client polls: GET /job/{job_id}
      ↓
   Status: pending → processing → completed
      ↓
Download results: GET /job/{job_id}/download
```

### 4. Celery Tasks

**Task: `deidentify_batch_task`**
```python
@celery_app.task(bind=True)
def deidentify_batch_task(self, job_id: str, notes: List[Dict], method: str):
    """
    Background task for batch de-identification

    Updates job status in database:
    - progress (processed_notes)
    - status (processing, completed, failed)
    - errors (list of failed notes)

    Stores results in Elasticsearch (deidentified_notes index)
    """
    job = get_job(job_id)
    total = len(notes)

    for i, note in enumerate(notes):
        try:
            result = deidentification_service.deidentify(
                note['text'],
                method
            )
            store_deidentified_note(job_id, note['id'], result)

            # Update progress every 10 notes
            if i % 10 == 0:
                update_job_progress(job_id, processed=i, total=total)
                self.update_state(state='PROCESSING', meta={'progress': i/total})

        except Exception as e:
            log_error(job_id, note['id'], str(e))

    finalize_job(job_id, status='completed')
    send_email_notification(job.user_email, job_id)
```

**Task Features**:
- Progress tracking (update every 10 notes)
- Error handling (log failed notes, continue processing)
- Cancellation support (check `self.request.should_terminate`)
- Result storage (Elasticsearch)
- Email notification on completion

### 5. Job Management

**Database Table**: `deidentification_jobs`
```sql
CREATE TABLE deidentification_jobs (
    job_id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    status VARCHAR(20),  -- pending, processing, completed, failed, cancelled
    method VARCHAR(20),  -- removal, replacement, generalization
    total_notes INT,
    processed_notes INT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    completed_at TIMESTAMP,
    error_count INT DEFAULT 0,
    notify_email VARCHAR(255)
);
```
