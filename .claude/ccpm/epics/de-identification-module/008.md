### 2. De-identification SOP Document

**Standard Operating Procedure Structure**:

```markdown
# De-identification Standard Operating Procedure

## 1. Purpose
- Enable secondary use of clinical data for research
- Maintain HIPAA Safe Harbor compliance (45 CFR §164.514(b)(2))
- Protect patient privacy while preserving clinical context

## 2. Scope
- Applies to all clinical notes de-identified for research
- Covers 18 HIPAA Safe Harbor identifiers
- Covers batch processing (1,000-10,000 notes)

## 3. Regulatory Framework
- HIPAA Safe Harbor Method (45 CFR §164.514(b)(2))
- 21 CFR Part 11 (Electronic Records)
- Institutional policies on data sharing

## 4. De-identification Methodology

### 4.1 Automated PHI Detection
- NLP-powered entity recognition using MedCAT
- Fine-tuned model on i2b2 2014 corpus (1,296 annotated notes)
- Detects 18 HIPAA Safe Harbor identifiers
- Confidence threshold: 0.7 (entities <0.7 flagged for review)

### 4.2 De-identification Methods
**Removal**: Replace PHI with [TYPE] placeholder
**Replacement**: Consistent synthetic mapping within document
**Generalization**: Dates → year only, Ages >89 → 90+

### 4.3 Human Review (Safety Net)
- All notes with confidence <0.8 manually reviewed
- Research coordinator reviews 10% random sample
- Manual annotation tool for catching missed PHI

### 4.4 Validation
- Regex patterns check for remaining PHI
- Clinical context preserved (readable notes)
- Audit trail links original → de-identified

## 5. Roles and Responsibilities

### Research Coordinator
- Upload clinical notes for de-identification
- Review flagged notes (confidence <0.8)
- Approve de-identified results
- Maintain audit trail

### Compliance Officer
- Review SOP annually
- Monitor audit logs
- Investigate privacy incidents
- Coordinate IRB submissions

### IT Administrator
- Maintain MedCAT service
- Configure Celery workers
- Monitor system performance
- Backup de-identified corpus

## 6. Quality Assurance

### Validation Metrics
- Precision >95% (low false positive rate)
- Recall >90% (catch 90% of PHI)
- F1 score >0.92 (harmonic mean)
- Monthly retraining on new annotations

### Performance Benchmarks
- Single note: <2 minutes (10-page note)
- Batch processing: 1,000 notes in <2 hours
- API response time: <3 seconds

## 7. Audit Logging (HIPAA Compliance)

### Required Audit Events
- User ID (who accessed PHI)
- Timestamp (when accessed)
- Action (deidentify, view, download)
- Resource ID (which notes/jobs)
- IP address (from where)
- Result (success/failure)

### Retention
- 8 years (HIPAA requirement)
- Stored in Elasticsearch (phi_audit_log index)
- Searchable by date, user, action

## 8. Security Controls

### Access Control
- RBAC: Only authorized users can de-identify
- JWT authentication (OAuth 2.0)
- 15-minute session timeout

### Encryption
- TLS 1.3 in transit
- AES-256 at rest
- No PHI in application logs

### Data Segregation
- Original notes: clinical_notes index (high security)
- De-identified notes: deidentified_notes index (lower security)
- Audit logs: phi_audit_log index (8-year retention)

## 9. Pilot Study Protocol

### Pilot Design
- 3 research projects (cardiology, oncology, diabetes)
- 500 notes de-identified per project
- Research coordinators review 10% sample (50 notes)
- Measure time savings and user satisfaction

### Success Criteria
- Zero PHI found in 10% sample review
- Time savings >90% vs manual (30 min → 2 min per doc)
- User satisfaction >4/5
- IRB accepts methodology without additional questions

## 10. Training Requirements

### User Training (2 hours)
- How to upload notes (CSV, database query)
- How to select de-identification method
- How to review results (side-by-side comparison)
- How to use manual annotation tool
- How to download results and audit reports

### Compliance Training (1 hour)
- HIPAA Safe Harbor requirements
- When de-identification is appropriate
- Limitations of automated de-identification
- Manual review responsibilities

## 11. Continuous Improvement

### Model Retraining
- Monthly retraining on manual annotations
- Track F1 score over time (detect model drift)
- Retrain if F1 drops below 0.90

### SOP Review
- Annual SOP review by compliance officer
- Update for regulatory changes
- Incorporate lessons learned from pilot

## 12. References
- HIPAA Safe Harbor Method: 45 CFR §164.514(b)(2)
- i2b2 2014 De-identification Challenge
- MedCAT Documentation
- Institutional Data Sharing Policy

## 13. Appendices

- Appendix B: Validation Report
- Appendix C: Confusion Matrix
- Appendix D: User Training Checklist
```

### 3. IRB Submission Package

**Required Documents**:
1. **Protocol Summary** (2-3 pages)
   - Project title, principal investigator
   - Purpose and significance
   - De-identification methodology
   - Data handling and storage
   - Risk assessment

2. **De-identification SOP** (12-15 pages, see above)

3. **Validation Report** (5-8 pages)
   - Gold standard corpus description
   - Precision, recall, F1 scores
   - Confusion matrix
   - Error analysis (which PHI types are missed)

4. **Informed Consent Waiver Request**
   - Justify why de-identified data qualifies for waiver
   - Cite HIPAA Safe Harbor compliance

5. **Data Security Plan** (3-5 pages)
   - Access controls (RBAC, authentication)
   - Encryption (TLS 1.3, AES-256)
   - Audit logging (8-year retention)
   - Backup and disaster recovery

6. **Pilot Study Plan** (3-4 pages)
   - 3 research projects, 500 notes each
   - 10% manual review
   - Success criteria

**Submission Timeline**:
- Week 9: Prepare documents
- Week 10: Submit to IRB
- Week 10-11: IRB review (2-week turnaround)
- Week 11: Address IRB questions (if any)
- Week 11: IRB approval
